Client reference

ApueClient is typed from the API definition — no code generation — and runs in Node and in browsers (web-platform APIs only; transports are pluggable). Imports: ApueClient, fetchTransport, Download and ApueError from apue; http2Transport from apue/http2; webSocketTransport and autoTransport from apue/websocket.

A transport is a small interface — request({ method, path, headers, body, signal }) returning status, headers and a body iterable, plus optional close() and baseUrl — so you can supply your own.

Several replicas

An upload lives on the replica that received it. When a server sets instance, upload ids carry the replica’s name (eu-1.<random>), and the client sends apue-replica: eu-1 with a unary call or batch whose input references uploads from that one replica — so a load balancer can route the call to them. The uploads themselves (/$uploads/eu-1.…) and download URLs (/$downloads/eu-1.…) are routed by path. See Deployment.

Downloads

url, pathThe download resource; url is absolute when the transport knows its base URL. Usable as a plain link until it expires.
size, type, sha256, expiresContent length, media type, SHA-256 (hex, if the server knows it), expiry (Date)
stream({ signal? })The content as it arrives; resumes with Range + If-Range within the retry budget; verifies the SHA-256 in Node
bytes({ signal? }), blob({ signal? })The whole content; bytes() verifies the SHA-256 with WebCrypto everywhere

A download URL works for downloads.ttlMs (15 minutes by default). An idempotent replay of the call that created it refreshes the URL, or answers 410 download-expired if it has already expired — the operation is not run again.

Errors

Every failure is thrown as an ApueError with status and problem (RFC 9457 fields plus extensions). Client-side validation failures are 400 validation-failed without a request being sent; an unknown operation name is 404; undecodable or truncated responses are 502. A cancelled call rejects with your signal’s reason. See Errors.
