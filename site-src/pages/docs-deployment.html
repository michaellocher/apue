Deployment

What a production deployment needs, with the settings that matter. Most of apü is stateless; the four things that aren’t each have a setting, and the routing for several replicas is verified end to end through a real nginx.

{{toc}}

Runtime

  • Node ≥ 26.11 and the package from its GitHub release (Getting started). The package ships JavaScript, so no type stripping is needed inside node_modules.
  • TLS is required: the server speaks HTTP/2 over TLS with HTTP/1.1 fallback (key, cert). Terminating TLS at a proxy is fine; the proxy then talks to the replica over TLS as well.
  • One process per CPU core is the usual layout; the server is single-threaded like any Node server.

Behind a proxy or load balancer

  • Streaming: turn request and response buffering off (proxy_request_buffering off and proxy_buffering off in nginx), so client streams, uploads, frames and SSE flow without delay, and allow long reads (proxy_read_timeout). apü sends a heartbeat after 15 s without other frames.
  • WebSockets (tier T3, browsers’ streaming uploads where fetch can’t stream them): forward Upgrade and Connection, or HTTP/2 extended CONNECT where the proxy supports it.
  • How nginx, Caddy, HAProxy and Envoy behave with apü traffic, measured: Caching, CDNs & proxies and Measurements.

A shared idempotency store

The built-in store is per process. For several replicas, pass an object with three methods over shared storage (for Redis, SET key … NX PX fits begin). Each may return a promise:

{{pre:ts|the shape the server expects}} interface IdempotencyStore { /** Atomically claims the key for this fingerprint, or reports why it cannot be claimed. */ begin(key: string, fingerprint: string): BeginResult | Promise; /** Stores the final response of a claimed key. */ complete(key: string, response: StoredResponse): void | Promise; /** Releases a claimed key without storing (e.g. on 5xx), so a retry can execute again. */ release(key: string): void | Promise; } type BeginResult = | { state: 'new' } | { state: 'replay'; response: StoredResponse } | { state: 'in-progress' } | { state: 'mismatch' }; interface StoredResponse { status: number; headers: Record; body: Uint8Array } {{/pre}}

A store that fails to record a result is reported to the logger; the response stands.

Routing by replica

With instance: 'eu-1', upload and download ids are eu-1.<random>. Route /$uploads/eu-1.… and /$downloads/eu-1.… by path, and calls that reference uploads by the apue-replica header that ApueClient sends. The configuration, as verified (docs/deployment/nginx.conf in the repository):

Verified with scripts/verify-deployment.ts (Docker): 30 of 30 calls with automatic uploads and downloads succeed through nginx across two replicas; with plain round robin, 0 of 30 do. Clients that don’t send the header (the generated Python, Go and Java clients) still work behind connection-affine balancing — L4, or HTTP/2 connections pinned to a replica — because an upload and the call that uses it travel on the same connection.

Persistent uploads (uploads.persistent) survive a restart of the same replica; give every replica its own uploads.directory (a lock refuses a second process). An idempotent replay refreshes the stored response’s download URLs, or answers 410 download-expired if one has already expired — never a dead link, never a second run.

Callers, limits, security

  • principal: name the caller (a user id) from your authentication. Quotas, idempotency keys, uploads and resume tokens are scoped to it. Without it, upload quotas count per client address — behind a proxy that is the proxy’s address for everyone. See Callers & auth.
  • CORS: list origins explicitly; credentials: true only with a list. Cross-origin WebSocket handshakes lose cookies unless CORS allows credentials (cross-site WebSocket hijacking).
  • Limits (defaults in parentheses): maxBodyBytes (1 MiB, JSON bodies), maxJsonDepth (64), maxBatchCalls (64), maxConcurrentStreams (256), idleTimeoutMs (120 s), bodyTimeoutMs (30 s), uploads.maxBytes / storeBytes / scopeBytes / scopeUploads, downloads.ttlMs. All options: Server reference.
  • The manifest (/.well-known/apue) and the OpenAPI document (/.well-known/openapi.json) are public by design; openapi: false drops the latter.

Shutdown, health, logging

  • On SIGTERM call server.close(): it stops accepting, lets calls finish for shutdownGraceMs (10 s by default), then ends the rest with a retryable 503 — clients retry or resume elsewhere. Keep the grace period below the orchestrator’s (Kubernetes: 30 s).
  • Health checks: answer a path such as /healthz in the fallback hook.
  • logger: { error(message, detail) } receives server-side failures — handler errors, output that doesn’t match its schema, an idempotency store failing to record. Client mistakes and disconnects are not logged.
