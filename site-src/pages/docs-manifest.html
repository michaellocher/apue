Manifest & codegen

Every apü server describes itself at /.well-known/apue. TypeScript clients that can import the API definition need nothing else; for everyone else, apue-types turns the manifest into a typed client module — TypeScript or Python.

{{toc}}

The manifest

GET {base}/.well-known/apue returns the operations with their effect, stream kind, JSON Schema for input and output, cache policy, deprecation and resumability. It is built once at startup (measured: 0.2–0.6 ms) and served with an ETag (its hash) and no-cache, so tools revalidate cheaply.

Next to the schemas it carries documentation derived from the definitions — nothing hand-written, no API change:

  • per operation: http (methods, path, media types, whether Idempotency-Key is honoured), errors (the protocol errors beyond the common ones) and example (placeholder input and output, validated against the operation’s own schema and left out if they don’t pass);
  • top level: http (conventions: ?i=, ?s=, headers, frames, bytes, downloads, WebSocket), errors (the common protocol errors) and limits from the server options.

An excerpt from the todo example’s manifest:

{{pre:json|GET /.well-known/apue (excerpt)}} { "apue": "draft-00", "ops": { "todos.create": { "effect": "unsafe", "stream": "none", "input": { "type": "object", "properties": { "title": { "type": "string", "minLength": 1, "maxLength": 200 } }, "required": ["title"] }, "output": { "type": "object", "properties": { "id": { "type": "integer" }, "…": "…" } }, "http": { "methods": ["POST"], "path": "/todos.create", "request": "application/json", "response": ["application/json"], "idempotencyKey": true }, "errors": [ { "status": 408, "type": "about:blank", "title": "Request Timeout" }, { "status": 409, "type": "https://apue.dev/problems/idempotency-key-in-progress", "title": "Idempotency Key In Progress" }, { "status": 422, "type": "https://apue.dev/problems/idempotency-key-reused", "title": "Idempotency Key Reused" } ], "example": { "input": { "title": "string" }, "output": { "id": 0, "title": "string", "done": true } } } }, "limits": { "maxBodyBytes": 1048576, "maxJsonDepth": 64, "maxBatchCalls": 64, "maxSelectPaths": 64, "bodyTimeoutMs": 30000, "heartbeatMs": 15000 } } {{/pre}}

The derived documentation grew the manifest 2.5–3.4× raw on three measured APIs (e.g. 1.9 → 5.4 KB), 1.2–1.5 KB gzipped. Errors a handler throws, and meaningful example values, can’t be derived and are not included.

API catalog

GET or HEAD /.well-known/api-catalog (RFC 9727) answers application/linkset+json with a service-desc link to the manifest, and itself carries Link: </.well-known/api-catalog>; rel="api-catalog" — generic discovery for crawlers and agents.

{{pre:console}} $ curl -s https://localhost:18443/.well-known/api-catalog {"linkset":[{"anchor":"https://localhost:18443/","service-desc":[{"href":"https://localhost:18443/.well-known/apue","type":"application/json"}]}]} {{/pre}}

TypeScript

A TypeScript client that can import the API definition is typed directly from it — no code generation. For code that can’t (another repository, another team), generate the same definition from a running server:

{{pre:sh}} node bin/apue-types.ts https://api.example --runtime ./apue/src --out api.ts # optional: --ca cert.pem, --name api {{/pre}}

The output is a defineApi(…) module with the same t.* schemas, importing api.ts and schema.ts from the --runtime directory. Generated for the todo example:

{{pre:ts|generated (excerpt)}} // Generated by apue-types from https://localhost:18556/.well-known/apue (draft-00). Do not edit. import { defineApi, op } from '../../src/api.ts'; import { t } from '../../src/schema.ts'; export const api = defineApi({ "todos.list": op({ effect: "safe", input: t.void(), output: t.array(t.object({ "id": t.number({ int: true }), "title": t.string({ min: 1, max: 200 }), "done": t.boolean() })), cache: {"maxAge":0} }), "todos.create": op({ effect: "unsafe", input: t.object({ "title": t.string({ min: 1, max: 200 }) }), output: t.object({ "id": t.number({ int: true }), "title": t.string({ min: 1, max: 200 }), "done": t.boolean() }) }), "todos.changes": op({ effect: "safe", stream: "server", resumable: true, input: t.void(), output: t.object({ "seq": t.number(), "todo": t.object({ "id": t.number({ int: true }), "title": t.string({ min: 1, max: 200 }), "done": t.boolean() }) }) }), // … }); {{/pre}}
  • Verified by a round trip: API → manifest → generated code → identical manifest.
  • The generator rejects JSON Schema keywords it can’t express instead of silently dropping constraints.
  • String patterns: JSON Schema pattern has no flags, so flags travel as x-apue-flags. Other validators see the unflagged pattern, so prefer patterns without i/m/s in public APIs.

Python

--lang python writes one self-contained module: a standard-library runtime (Python ≥ 3.11, HTTP/1.1 over TLS with keep-alive), the API’s types as TypedDicts and a Client with one method per operation (todos.get → todos_get, Python keywords escaped).

{{pre:sh}} node bin/apue-types.ts https://api.example --lang python --out api.py {{/pre}} {{pre:py|using the generated module}} from api import ApueError, Client with Client("https://localhost:8443", cafile="certs/cert.pem") as c: todo = c.todos_create({"title": "buy milk"}) # POST + Idempotency-Key print(c.todos_get({"id": todo["id"]})) # GET /todos.get?i=... try: c.todos_create({"title": ""}) except ApueError as e: print(e.status, e.type, e.detail) # 400 https://apue.dev/problems/validation-failed … for change in c.todos_changes(): # a server stream print(change["seq"], change["todo"]["title"]) break {{/pre}}

Run against the todo example; it printed the todo, 400 https://apue.dev/problems/validation-failed input does not match the schema and 0 buy milk.

Covered: unary calls (GET ?i= for cacheable reads with near-canonical JSON, POST otherwise), Idempotency-Key for non-safe calls (idempotency_key= to set your own), retries for safe and keyed calls on connection loss and on 429/503 honouring Retry-After, server streams, client and bidi streams (half duplex), RFC 9457 problems including END-frame errors, deadlines (timeout_ms=), bytes in messages, uploads for bytes and file inputs (file objects streamed chunked) and t.download() outputs (resumed with Range + If-Range, SHA-256 verified).

Not covered: resuming broken streams, batches, full duplex, compression and client-side validation (the server validates).
