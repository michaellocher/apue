Spec & research

The normative text is SPEC-DRAFT.md (draft 01, 2026-10-28) in the apü repository, next to eleven research notes and a log of every spike. The repository is private research for now; this page summarises what is in it and where to look.

{{toc}}

Goals and non-goals

Goals: one call model for unary, server-, client- and bidirectional streaming with one frame format on every transport; high throughput and short time to first byte, compression, multiplexing; defined purely in RFC 9110 semantics so HTTP/1.1, HTTP/2 and HTTP/3 all work; usable from every browser via fetch() and through ordinary CDNs, proxies and load balancers; fix the top problems of existing styles; TypeScript-first schemas with a language-neutral manifest.

Non-goals: a query language; server-side sessions or sticky connections; relying on trailers, server push, 1xx responses, custom HTTP/2 frames or settings, h2c in browsers, or GET with a body.

Open questions

Resolved during the drafting: idempotent operations use POST + key, not PUT; QUERY through CDNs (rejected by CloudFront and Akamai → POST fallback); browser duplex via the WebSocket tier; compression per stream with per-burst flush; projection syntax as dotted paths; CBOR closed with measurements; resumable uploads implemented; message-level CREDIT frames not specified (pacing by patterns); callers and auth via the principal hook; long-running operations as a pattern.

Still open in draft 01:

  • WebTransport (T4) and HTTP/3 in Node. The official Node 26.12.1 build is compiled without QUIC (node_use_quic: false); node:quic needs a custom build. HTTP/3 today means an HTTP/3-terminating proxy or CDN in front.
  • Generators for more languages. TypeScript and Python exist; Go, Kotlin/Java and Swift are open.
  • A full DPoP profile — deferred until a DPoP authorization server is in play; the groundwork exists.
  • Problem type namespace: https://apue.dev/problems/ is kept; the URIs are identifiers and don’t resolve to documents yet.
