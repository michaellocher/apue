BetaToolkit 0.1.0-beta · spec draft 01

Typed API operations on plain HTTP.

apü maps typed operations onto ordinary HTTP — reads are cacheable GET requests, writes carry idempotency keys, errors are real status codes — and adds streaming in every direction, resumable streams and uploads, and pipelined batches that work from browsers and through CDNs and proxies.

{{pre:console|npm}} $ npm install apue@beta {{/pre}}

Node ≥ 26.11 for the server and the Node client; the core runs in browsers too. No runtime dependencies. 404 tests, run in Chrome, Firefox and WebKit and through nginx, Caddy, HAProxy and Envoy. Betas may still change the wire format and APIs — every change is in the changelog.

Quick start

Define it once. Typed end to end.

Schemas are TypeScript values. The same definition validates on both sides, types the handlers and the client, and produces a language-neutral manifest. TypeScript clients need no code generation.

1 · The contract

Each operation declares its effect — safe, idempotent or unsafe — and its stream kind. That decides the HTTP method, caching and retries.

  • safe → GET, cacheable, ETag/304
  • unsafe → POST + Idempotency-Key, safe to retry
  • stream: 'server', resumable → many messages, resumed after a lost connection
{{readme:0|api.ts}}

2 · The server

Handlers get validated input; output is validated and stripped to the schema before it leaves. A stream is an async generator that checkpoints as it goes.

Run it with node server.ts — Node 26 runs TypeScript directly.

3 · The client

Inputs and outputs are typed from the same definition. In browsers, use fetchTransport from apue, or autoTransport from apue/websocket for streaming uploads everywhere.

What you get

Everything an API needs, on HTTP’s own terms

Everything below is implemented in the reference implementation and covered by its tests.

Operations on plain HTTP

Safe ops are GET /op?i=… (RFC 8785 canonical JSON), QUERY or HEAD; others are POST. Strong ETags, 304s, Cache-Control — so browser caches and CDNs work.

Streaming tiers, browsers included

Server, client and bidirectional streams. Response streams over fetch everywhere; full duplex over node:http2; request streams over fetch in Chromium and over WebSocket in every browser, with HTTP/2-style flow control.

Resumable streams and uploads

Streams carry signed checkpoints; after a lost connection the client resumes on any replica, exactly once. Uploads follow the IETF resumable-upload draft.

Binary data, no base64

t.bytes() as raw BLOB frames, t.file() inputs streamed to handlers, t.download() outputs served under short-lived URLs with Range, If-Range and Repr-Digest.

Pipelined batches

Dependent calls in one round trip with typed ref()s; results stream back out of order as each lane ends; failures stay per lane (424 for dependents).

RFC 9457 errors

Real HTTP status codes with application/problem+json, a retryable flag and per-field validation errors — visible to proxies, dashboards and generic clients.

Idempotency keys

Every non-safe unary call carries an Idempotency-Key. A retry with the same payload is replayed (apue-replayed: ?1), a different payload is a 422, a call still running a 409.

Manifest and OpenAPI 3.2

Every server describes itself at /.well-known/apue and /.well-known/openapi.json — derived from the definitions, with JSON Schema, examples and the errors each operation can return.

Also: field selection (?s=), deadlines (apue-timeout), zstd/brotli/gzip compression flushed per frame burst, heartbeats, CORS, CDN-Cache-Control and cache groups, an RFC 9727 API catalog, bounded graceful shutdown.

Clients

One server, clients for every stack

TypeScript gets its types straight from the definition. Everyone else points apue-types at a running server: it reads the manifest at /.well-known/apue and writes one self-contained client file that needs nothing but the language’s standard library.

TypeScriptno codegen

Import the API definition and every call is typed. Without access to it, apue-types generates the same defineApi(…) module from the manifest. Browsers and Node.

Streams: full duplex over HTTP/2 in Node; in browsers over fetch, or WebSocket where fetch can’t stream uploads.

Pythongenerated

One module, standard library only (Python ≥ 3.11): unary calls, resumable server streams, batches, compression, client-side validation, uploads and downloads.

Client and bidi streams: half duplex — http.client sends the whole body first.

Gogenerated

One gofmt-clean file, standard library only (Go ≥ 1.24), a method per operation taking a context.Context. Not yet: resuming broken streams, batches, compression, client-side validation.

Client and bidi streams: full duplex over HTTP/2.

Javagenerated

One Java 17 source file, JDK only: records for the types, a thread-safe client over java.net.http. Kotlin calls it too. Not yet: resuming broken streams, batches, compression, client-side validation.

Client and bidi streams: half duplex — JDK 17’s HttpClient answers only after the request body.

Swiftgenerated

One Swift 6 file, Foundation only: Codable types and a Client with async methods over URLSession, certificate pinning on Apple platforms. Tested on macOS and Linux. Not yet: resuming broken streams, batches, compression, client-side validation.

Client and bidi streams: full duplex over HTTP/2 on Apple platforms; half duplex on Linux (inputs collected first).

OpenAPI 3.2on by default

Every server also describes itself at /.well-known/openapi.json, derived from the same definitions and built on first request. Not described there: /$batch and the WebSocket tier.

{{pre:console|apue-types}} $ npx apue-types https://api.example --out api.ts $ npx apue-types https://api.example --lang python --out api.py $ npx apue-types https://api.example --lang go --package api --out api.go $ npx apue-types https://api.example --lang java --package com.example.api --out Api.java $ npx apue-types https://api.example --lang swift --out Api.swift {{/pre}}

Production

Built to run behind a load balancer

Most of apü is stateless. The few things that aren’t each have a setting, and the routing for several replicas is verified end to end through a real nginx.

Replicas

A shared resume.secret lets any replica resume a stream; an idempotency store over shared storage (its contract allows promises) replays a retry wherever it lands. Uploads and downloads carry the replica’s instance name, and clients send apue-replica, so the balancer routes to the data: 30 of 30 calls through nginx across two replicas, 0 of 30 with plain round robin.

Shutdown and failures

close() lets calls finish for shutdownGraceMs (10 s), then ends the rest with a retryable 503 — clients retry or resume elsewhere. A logger option receives server-side failures; client mistakes and disconnects are not logged.

Limits and callers

Body size, JSON depth, batch size, concurrent streams, idle and body timeouts, upload quotas — all bounded by default. A principal hook names the caller; quotas, keys, uploads and resume tokens are scoped to it. DPoP proofs bind tokens to the client’s key (verifier and signer).

On the wire

It is just HTTP

Real curl sessions against the example server (examples/todo, HTTP/2). Nothing here needs an apü client.

A read is a cacheable GET

The input travels as canonical JSON in ?i=, so equal inputs make equal URLs — and equal cache keys. The strong ETag makes revalidation a 304.

{{pre:console|safe op → GET with canonical input}} $ curl -i 'https://localhost:18443/todos.get?i=%7B%22id%22%3A1%7D' HTTP/2 200 accept-query: "application/json" content-type: application/json cache-control: no-cache etag: "wknydwJzvZ1RXhXqTUxSmI" {"id":1,"title":"buy milk","done":false} {{/pre}}

A retried write is replayed, not re-executed

The second attempt with the same Idempotency-Key and payload gets the stored response, marked apue-replayed: ?1.

{{pre:console|unsafe op → POST + Idempotency-Key (second attempt)}} $ curl -i -X POST -H 'content-type: application/json' \ -H 'idempotency-key: "demo-1"' -d '{"title":"buy milk"}' \ https://localhost:18443/todos.create HTTP/2 200 content-type: application/json cache-control: no-store apue-replayed: ?1 {"id":1,"title":"buy milk","done":false} {{/pre}}

Errors are status codes with problem details

A real 400, an RFC 9457 body, and a type URI that resolves to its documentation.

{{pre:console|validation error → 400 application/problem+json}} $ curl -i -X POST -H 'content-type: application/json' \ -d '{"title":""}' https://localhost:18443/todos.create HTTP/2 400 content-type: application/problem+json cache-control: no-store {"type":"https://apue.dev/problems/validation-failed", "fields":[{"path":"title","message":"shorter than 1"}], "title":"Validation Failed","status":400, "detail":"input does not match the schema"} {{/pre}}

From docs/wire.md in the repository (TLS options omitted, the problem body wrapped for width). More on the wire format page.

Why

The problems it addresses

apü started from a catalogue of what existing API styles get wrong (research note 01). Each row is a problem from that catalogue and apü’s answer, as specified in the draft.

  • No single model for request/response, streaming and realtime; gRPC’s bidirectional streams don’t run in browsers.One frame format on every transport — fetch, native HTTP/2 duplex and WebSocket — with streaming tiers chosen per environment.
  • Reads tunnelled through POST lose HTTP caching (GraphQL, gRPC).Safe operations are GET with a canonical input in the URL, or QUERY (RFC 10008) for large inputs with a POST fallback; ETags and Cache-Control.
  • Errors hidden behind HTTP 200; no portable error and partial-failure model.Real status codes and RFC 9457 problem details; streams fail early with a real status or later with an in-band END frame; batches fail per lane.
  • Dependent calls cost one round trip each.Pipelined batches: later calls reference earlier outputs with $ref, all in one request.
  • Over-fetching, query-cost attacks, per-field authorization.No query language: field selection validated against the output schema (at most 64 paths), limits declared in the schema.
  • Idempotency, retries and long-running operations are reinvented everywhere.The effect drives retry rules; Idempotency-Key on every non-safe call; deadlines; resumable streams; a long-running-operation pattern built from these.
  • Versioning and evolution pain.Additive evolution, unknown input fields ignored, Deprecation/Sunset headers, a manifest per server.
  • Load balancers, proxies and debugging; large and resumable binaries.Stateless servers (no sessions; resume tokens work on any replica), heartbeats, anti-buffering headers, JSON by default, an SSE view for curl; raw binary frames, resumable uploads and Range downloads.

Numbers, with their conditions

From the repository’s benchmark and proxy reports (Node 26.12.1, TLS + HTTP/2, JSON, 2026-10-28). They describe this reference implementation on these machines — not a general verdict on any protocol.

5–12×download speed from tuned HTTP/2 windows4 MiB download at 63 ms RTT: 0.56 MiB/s with Node’s 64 KiB default window vs 2.9–7.0 MiB/s with apü’s 4 MiB / 32 MiB (varied between runs).

The cost: against a hand-written node:http2 handler that validates nothing, apü reaches 62 % of its unary throughput and 75 % of its stream throughput locally, and 95 % of its unary throughput at 63 ms RTT. Details, caveats and all scenarios: Measurements.

Status

Beta, honestly labelled

The toolkit is apue 0.1.0-beta on npm; the protocol is spec draft 01, written alongside spikes S0–S32. Each spike’s goal, findings and measurements are logged in the spec, and every open question is now decided — or blocked by the platform.

S0 skeletonS31–S32 beta hardening

33 spikes, from the project skeleton (S0) to production readiness (S28), the Python, Go and Java clients (S29), beta hardening in WebKit on Linux and over emulated networks (S30–S31) and the release dry run, Swift on Linux and DPoP (S32); the two newest are highlighted.

Ready in the beta

  • The full HTTP mapping, framing and streaming tiers T0–T3
  • Resumable streams and uploads, downloads, pipelined batches
  • Idempotency, compression, CORS, callers (principal hook), DPoP proofs
  • Replicas: shared resume secret and idempotency store, routing by instance
  • The manifest, OpenAPI 3.2, and TypeScript, Python, Go, Java and Swift clients
  • Published as apue: JavaScript + declarations, no runtime dependencies

Open blocked or decided against

  • Blocked by the platform: WebTransport (tier T4) and HTTP/3 in Node — the official Node 26 build has no QUIC. apü works behind an HTTP/3-terminating proxy.
  • Decided against: per-frame compression, $map in batches, Location on QUERY responses, CBOR
  • Betas may still change the wire format and APIs; every change is listed in the changelog
