Caching, CDNs & proxies

Because safe operations are ordinary GETs with deterministic URLs, every HTTP cache between client and server can do its job. This page covers the headers apü sets, and what was observed through real proxies.

On this page

  • Cache headers from the operation

  • Through real proxies
  • Behind load balancers
  • Compression

Cache headers from the operation

  • ETag: safe responses carry a strong ETag, the SHA-256 of the representation (per content coding and per field selection). If-None-Match → 304 (weak comparison).
  • Cache-Control comes from the operation’s cache declaration: max-age, stale-while-revalidate, private. Without one, safe responses are no-cache — stored, but revalidated with the ETag every time. Non-safe operations and streams are no-store.
  • Vary for accept, accept-encoding and origin as applicable. HEAD works wherever GET does.
  • CDN-Cache-Control (RFC 9213): cache.cdnMaxAge sets CDN-Cache-Control: max-age=N; CDNs use it instead of Cache-Control, browsers keep max-age.
  • Cache groups (RFC 9875): cache.groups sends Cache-Groups; invalidates on a non-safe operation sends Cache-Group-Invalidation on successful responses, so caches that support it can drop the group. At most 32 groups of 1–32 printable ASCII characters, checked by op().

QUERY and CDNs

Reads whose input doesn’t fit a 2 KiB URL use QUERY (RFC 10008). It is cacheable by definition, but no CDN caches it today: CloudFront answers 403, Akamai 501; nginx, Envoy ≥ 1.40, HAProxy and Fastly forward it. The client falls back to POST when QUERY is rejected. planned QUERY responses with Location / Content-Location pointing to a GET-able URL.

  1. Request/response traffic works through every proxy with default settings, including QUERY, idempotency keys, ETags and zstd.
  2. Streaming responses are never buffered: nginx because apü sends X-Accel-Buffering: no (all four ignore Incremental: ?1 today); Caddy, HAProxy and Envoy stream by default.
  3. Full duplex needs proxy_request_buffering off in nginx; WebSockets need upgrade headers in nginx and upgrade_configs in Envoy. Caddy and HAProxy work with their defaults.
  4. HTTP/2 backpressure is hop-by-hop, so proxies let a server run 5.8–32 MiB ahead of a stalled consumer; the WebSocket tier’s end-to-end credit held at the client’s 4 MiB window behind every proxy that passes WebSockets.
  5. Envoy surfaced a crash: when a client cancelled, Envoy reset the upstream stream with INTERNAL_ERROR instead of CANCEL, and the unhandled error killed the server. Fixed, with a regression test for the relevant reset codes.
  6. Behind Caddy, apü compresses responses the client never asked to be compressed: Caddy’s upstream transport adds Accept-Encoding: gzip and decompresses for the client.

The tuned configurations are bench/proxy/nginx-tuned.conf and bench/proxy/envoy-tuned.yaml in the repository.

Behind load balancers

  • Servers are stateless: no sessions, no sticky connections. Resume tokens are self-contained and verified by any replica with the shared secret.
  • Heartbeats every 15 s of silence keep streams alive through intermediary timeouts of 15–125 s.
  • Per connection, the server limits concurrent streams (maxConcurrentStreams, 256 — Node’s own default is unlimited), closes idle sessions with GOAWAY (120 s), bounds the time a unary body may take (30 s → 408) and the size of messages (413).

Compression

Accept-Encoding is negotiated with q-values; the server prefers zstd, then brotli, then gzip, at levels zstd-3, brotli-4 and gzip-1 (brotli-11 runs at about 1 MiB/s — never on the fly). Unary bodies are compressed from 1 KiB, off the event loop from 64 KiB, with Vary: accept-encoding and an ETag per coding. Streams flush the compressor after every burst of frames, so time to first byte is unaffected. On a 100 Mbit/s, 63 ms RTT link, zstd gave 2.7× stream and 1.8× bulk throughput. Don’t mix secrets with attacker-echoed data in one compressed stream.
