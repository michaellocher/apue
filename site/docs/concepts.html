Operations & HTTP mapping

An apü API is a set of operations. Each one declares what it does to server state; apü derives the HTTP method, cacheability and retry rules from that — so the right thing happens on the wire without per-endpoint decisions.

Operations

An operation is identified by a dotted name such as users.get (letters, digits, _ and -, each segment starting with a letter) and is served at {base}/{op}: the name in the path is easy to route and compresses well in HPACK.

PropertyValuesWhat it controls
effectsafe · idempotent · unsafeHTTP method, cacheability, retry and 0-RTT eligibility
streamnone (default) · server · client · bidiBody framing and transport tier (Streaming)
input, outputschemas (t.*)Validation on both sides, output stripping, the manifest. For streams: the schema of each message.
cachemaxAge, staleWhileRevalidate, private, cdnMaxAge, groupsCache-Control and CDN headers for safe operations (Caching)
invalidatescache group namesCache-Group-Invalidation on successful non-safe calls
resumablebooleanServer streams with checkpoints (Resumable streams)
deprecatedsince, sunset, linkDeprecation (RFC 9745), Sunset (RFC 8594) and Link headers
descriptiontextThe manifest

op() rejects definitions that can’t work, at startup rather than in production:

  • only server streams can be resumable, and only if safe or idempotent (resuming re-sends the request);
  • only safe operations may declare cache; only non-safe ones invalidates; cdnMaxAge not together with private; at most 32 cache groups of 1–32 printable ASCII characters;
  • t.file() only in unary inputs, t.download() only in outputs and never with a cache maxAge/cdnMaxAge (download URLs expire);
  • a sunset earlier than since.

Effects and HTTP methods

effectstreamRequest
safenone, serverGET {base}/{op}?i={canonical input} if the path is at most 2 KiB, else QUERY {base}/{op} with the JSON as body. HEAD wherever GET works.
idempotentnonePOST + Idempotency-Key; retries allowed
unsafenonePOST + Idempotency-Key; retries allowed because of the key
anyclient, bidiPOST with a request stream; never retried (a stream can’t be replayed)

The server enforces the mapping: any other method gets 405 with an Allow header. Idempotent operations use POST with a key rather than PUT, because PUT means “replace the target resource”.

Canonical GET inputs

The i parameter is the input as RFC 8785 (JCS) canonical JSON, percent-encoded: object keys sorted, numbers and strings serialised deterministically. The same input therefore always produces the same URL — and the same cache key in every browser cache and CDN.

QUERY and the POST fallback

When the URL would be longer than 2 KiB, the client sends QUERY (RFC 10008), a safe method with a body; responses advertise it with Accept-Query: "application/json". Some intermediaries reject it — CloudFront with 403, Akamai with 501, Envoy before 1.40 — so on 400, 403, 405 or 501 the client repeats the request as POST, and remembers that only if POST then fares better. nginx, Envoy ≥ 1.40, HAProxy and Fastly forward QUERY; no CDN caches it today.

Idempotency keys

Every non-safe unary call carries Idempotency-Key, a client-generated UUID sent as a Structured Field string (idempotency-key: "…"). The server follows the IETF idempotency-key draft:

  • Scope = operation + caller (the principal, else a hash of Authorization) + key; fingerprint = SHA-256 of the canonical input.
  • Same key and payload → the stored response is replayed with apue-replayed: ?1 (an apü extension; the draft defines no such header).
  • Same key, different payload → 422 idempotency-key-reused.
  • Original still running → 409 idempotency-key-in-progress with retryable: true.
  • Handler 4xx responses are stored; 5xx and client aborts release the key, so a retry executes again.

The default store is in memory (24 h, 10,000 entries). Several replicas need a shared store with the same contract — begin, complete, release, each of which may return a promise — so a retry that reaches another replica is replayed (Server reference, Deployment); idempotency: false turns the feature off.

Retries

The client retries (default 2 retries, full-jitter exponential backoff) on transport errors, 503 and 429 (honouring Retry-After as seconds or an HTTP date, capped at the maximum backoff) and 409 with retryable: true — but only for safe operations or keyed requests. A 504 deadline is not retried.

Validation and output stripping

  • Input is validated on the client — invalid input is never sent — and again on the server (400 with per-field fields).
  • Unknown input fields are dropped, not rejected, so newer clients can talk to older servers.
  • Output is validated and stripped to the schema before it is sent: fields the schema doesn’t list never leak. Invalid output is a 500.
  • Incoming JSON is limited to 64 levels of nesting (maxJsonDepth), bodies to 1 MiB by default (maxBodyBytes, 413 beyond).

Field selection

?s=a,b.c asks for only some output fields — on any method; for GET it is part of the cache key. Paths are validated against the output schema before the handler runs (unknown paths: 400 invalid-selection), at most 64, through objects, arrays, optional and nullable fields; selecting a parent includes its children. Selection is applied after output validation, so only schema fields can be selected, and the ETag covers the projected body. There is no query language and there are no joins: the cost of a call stays bounded by the schema.

The typed pick() checks paths at compile time (up to four levels) and returns a DeepPartial of the output.

Deadlines and cancellation

A call’s deadline travels as apue-timeout: <ms> (over WebSocket: ?timeout=). When it passes, the server aborts the handler’s ctx.signal and answers 504 deadline-exceeded — also when a producer ignores the signal. Client cancellation (an AbortSignal, or break out of a stream loop) resets the HTTP/2 stream and aborts the handler.

Evolution and deprecation

Within a major version only additive changes are allowed. An operation is retired by marking it deprecated: responses then carry Deprecation (RFC 9745), Sunset (RFC 8594) when a date is set, and Link: <…>; rel="deprecation" for a migration guide.

Reserved paths

PathPurpose
/.well-known/apueThe manifest
/.well-known/api-catalogRFC 9727 API catalog
/$batchPipelined batches
/$uploadsResumable uploads (when enabled)
/$downloads/…Download resources

Operation names start with a letter, so they can’t collide with these. Every other path can be served by the application through the server’s fallback hook — for example the web app itself, which then needs no CORS.

Schema types

Schemas come from a small builder with static type inference (Infer<typeof S>), written in erasable TypeScript only. Each schema validates, infers its TypeScript type and exports JSON Schema for the manifest.

BuilderTypeScript typeNotes
t.string({ min?, max?, pattern? })stringLength bounds; a RegExp pattern (flags travel as x-apue-flags; g and y are refused)
t.number({ int?, min?, max? })numberFinite numbers; int → JSON Schema integer

t.download({ type? })DownloadSource / client: DownloadLarge outputs, served with Range

t.void()voidNo payload

JSON is the encoding (bigint and decimal values as strings). A CBOR encoding was evaluated with measurements and closed: codec and validation are about 11 % of server CPU in a unary call, generic CBOR was no faster than JSON and often larger after compression (research note 11).
