Errors

An apü error is an HTTP status code with an RFC 9457 problem details body — never a 200 with an error inside. Streams and batches, which can fail after their headers are sent, carry the same status and problem in-band.

  • Errors in streams
  • Errors in batches

Unary calls

A failed unary call answers with its real status and Content-Type: application/problem+json:

  • Generic errors use the type about:blank with the HTTP status phrase as title — e.g. 405 Method Not Allowed (with an Allow header), 408 when a request body doesn’t arrive within bodyTimeoutMs, 413 beyond the size limits, 415 for a wrong content type.
  • apü’s own protocol errors have type URIs under https://apue.dev/problems/ (below).
  • Extension members: retryable (boolean) and fields (per-field validation errors, [{ path, message }]).
  • Unexpected handler errors become 500 without details; they are logged on the server.

Throwing and catching

Handlers throw ApueError(status, title, detail?, extensions?, headers?). Its extension members end up in the problem, its headers in the response. Clients throw the same class, carrying the decoded problem.

The generated Python client raises ApueError as well, with status, type, title, detail, retryable and the whole problem.

Problem types

These URIs are identifiers in the https://apue.dev/problems/ namespace. The draft does not yet publish a document at each URI; this table is their description.

validation-failed400Input doesn’t match the schema (fields lists each problem); also an unknown, incomplete or expired upload reference
unknown-operation404No operation with that name
invalid-selection400A ?s= path isn’t in the output schema, or more than 64 paths
malformed-stream400 (request) · 502 (client, response)Frames that can’t be decoded: invalid JSON, a BLOB frame for an operation without bytes, a lane other than 0 in a request stream, an END without status
truncated-stream400 (request) · 502 (client, response)A framed body ended without its END frame — e.g. a proxy cut the connection
deadline-exceeded504The apue-timeout deadline passed; not retried by clients
idempotency-key-in-progress409A call with the same key is still running; retryable: true
idempotency-key-reused422The key was used before with a different payload
invalid-batch400A batch failed structural validation (all or nothing)
unresolvable-reference400A $ref path doesn’t exist in the referenced output

invalid-resume-token400A resume token that is invalid, foreign, expired or for another input

Other statuses you will see: 429/503 (retried by clients, honouring Retry-After), 503 with retryable: true when a server shuts down, 507 when a client’s upload quota is full (retrying won’t help, deleting will), and resumable-upload problems from the IANA registry such as mismatching-upload-offset (409) and inconsistent-upload-length (400).

Errors in streams

A streamed response wants its headers out fast, but then can no longer change its status. apü handles both cases:

  • Early failure — before the first item and within the commit window (default 50 ms): the response is a real status with problem details, just like a unary call. Proxies and dashboards see it.
  • Later failure — headers are already committed: the stream ends with an END frame {"status": <http status>, "problem": {…}}. Clients raise it as an ApueError after the items that came before it.

Every lane must end with END. A body that stops without one is treated as truncated (502 on the client); a resumable stream that already has a checkpoint is resumed instead.

Errors in batches

A batch answers 200 once it is accepted; every call (lane) then ends with its own END frame. A failed call rejects only its own result; calls that reference it end with 424 failed-dependency, transitively; independent lanes are unaffected. Structural problems — unknown operations, references to later calls, too many calls — reject the whole batch up front with 400 invalid-batch. See Pipelined batches.

In the manifest

The manifest lists the protocol errors every operation can return, and per operation the extra ones (408 for JSON bodies, malformed/truncated streams for request streams, 409/422 for keyed calls, invalid resume tokens). A drift test provokes every protocol error against every kind of operation and fails if the server returns one the manifest doesn’t list. Errors a handler throws are not derivable and not listed.

apü

An API protocol built on plain HTTP semantics. Research draft 01, October 2026 — not a stable standard, and no package is published yet.

The name is written apü; URLs, headers and media types use apue.
