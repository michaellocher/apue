Clients, manifest & OpenAPI

Every apü server describes itself at /.well-known/apue and, as OpenAPI 3.2, at /.well-known/openapi.json. TypeScript clients that can import the API definition need nothing else; for everyone else, apue-types turns the manifest into a client — TypeScript, Python, Go or Java.

The manifest

GET {base}/.well-known/apue returns the operations with their effect, stream kind, JSON Schema for input and output, cache policy, deprecation and resumability. It is built once at startup (measured: 0.2–0.6 ms) and served with an ETag (its hash) and no-cache, so tools revalidate cheaply.

Next to the schemas it carries documentation derived from the definitions — nothing hand-written, no API change:

  • per operation: http (methods, path, media types, whether Idempotency-Key is honoured), errors (the protocol errors beyond the common ones) and example (placeholder input and output, validated against the operation’s own schema and left out if they don’t pass);
  • top level: http (conventions: ?i=, ?s=, headers, frames, bytes, downloads, WebSocket), errors (the common protocol errors) and limits from the server options.

An excerpt from the todo example’s manifest:

The derived documentation grew the manifest 2.5–3.4× raw on three measured APIs (e.g. 1.9 → 5.4 KB), 1.2–1.5 KB gzipped. Errors a handler throws, and meaningful example values, can’t be derived and are not included.

API catalog

GET or HEAD /.well-known/api-catalog (RFC 9727) answers application/linkset+json with a service-desc link to the manifest, and itself carries Link: </.well-known/api-catalog>; rel="api-catalog" — generic discovery for crawlers and agents.

TypeScript

OpenAPI 3.2

GET or HEAD /.well-known/openapi.json answers an OpenAPI 3.2 document (application/openapi+json; version=3.2.0, ETag/304, no-cache), linked as a second service-desc from the API catalog. It is derived from the operation definitions only, built on the first request and cached — nothing is spent if nobody asks (the todo example: 29 KB raw, 4.2 KB gzipped, 0.3 ms).

  • On by default: it says nothing the public manifest doesn’t. openapi: false turns it off; openapi: { title, version, description, servers } fills info and servers.
  • Each operation as the server routes it: reads as get (input in the i query parameter), head, query and post; everything else post. Idempotency-Key where honoured, apue-timeout, apue-resume, ?s=, ETag/304.
  • Responses: JSON outputs; framed bodies as opaque binary with the per-message schema in x-apue-message-schema; text/event-stream with an itemSchema for response streams; RFC 9457 problem responses per status from the protocol errors; placeholder examples; upload, blob and download references.
  • Not described: /$batch and the WebSocket tier.
  • The tests validate the documents against the official OAS 3.2 JSON Schemas.

Generated clients

A TypeScript client that can import the API definition is typed directly from it — no code generation. For everything else, apue-types reads a running server’s manifest and writes one self-contained file:

Options: --ca cert.pem for a private certificate authority; for TypeScript --runtime (default apue) and --name (default api). The generator rejects JSON Schema keywords it can’t express instead of silently dropping constraints. The same generators are a library: generateApi, generatePython, generateGo and generateJava from apue/codegen.

TypeScript

The output is a defineApi(…) module with the same t.* schemas, importing from apue; use it with ApueClient like a hand-written definition. Verified by a round trip: API → manifest → generated code → identical manifest. Generated from the quick start’s server:

String patterns: JSON Schema pattern has no flags, so flags travel as x-apue-flags. Other validators see the unflagged pattern, so prefer patterns without i/m/s in public APIs.

Python

One module: a standard-library runtime (Python ≥ 3.11, HTTP/1.1 over TLS with keep-alive, one call at a time per client), the types as TypedDicts, a Client with one method per operation (todos.create → todos_create; Python keywords and client members get a trailing _) and a Batch with the same methods.

Covered: unary calls (GET ?i= with canonical JSON, QUERY above 2 KiB with the POST fallback), Idempotency-Key (idempotency_key= to set your own), retries on connection loss, on 429/503 honouring Retry-After and on retryable 409s, resumable server streams, client and bidi streams (half duplex: http.client sends the whole body before reading), pipelined batches, compressed responses, client-side validation against the manifest’s JSON Schema with JavaScript regex semantics, RFC 9457 problems including END frames, deadlines (timeout_ms=), bytes, uploads for bytes and file inputs, and t.download() outputs (resumed with Range, SHA-256 verified).

Go

One gofmt-clean file: a standard-library runtime (Go ≥ 1.24, net/http, HTTP/2 over TLS), structs with JSON tags (optional fields as pointers, named string types for enums, []byte for bytes) and a Client with one method per operation taking a context.Context (todos.create → TodosCreate). Schemas Go can’t express are refused, not weakened.

Covered: unary calls (the same canonical ?i= URL as the TypeScript client, POST above 2 KiB, Idempotency-Key, retries), server streams (Recv, or range over All() — leaving the loop cancels), client and bidi streams full duplex over HTTP/2, problems as *api.Error (also from END frames), deadlines and context cancellation, bytes, uploads and downloads (resumed with Range, SHA-256 verified). Not covered: resuming broken streams, batches, QUERY, compression, client-side validation.

Java

One Java 17 source file, JDK only and pure ASCII: records for the types (optional and nullable members as Optional<T>), enums that keep their JSON names, and a thread-safe Client over java.net.http.HttpClient (HTTP/2; a private CA via Options.trustedCertificates(…)). Kotlin code calls it as it is.

Covered: unary calls, server streams as an iterable, closeable Stream (closing resets the HTTP/2 stream), client and bidi streams (half duplex: JDK 17’s HttpClient exposes a response only after the request body), problems as ApueException including END frames, deadlines, bytes, uploads (byte[], Path, InputStream) and downloads (resumed with Range, SHA-256 verified). Not covered: resuming broken streams, batches, compression, QUERY, client-side validation; enums are strict.

Other languages

  • in progress A Swift generator — not part of the beta yet.
  • Anything else: the manifest and the OpenAPI document describe the HTTP contract, and the wire format the frames.

The three usage examples above were run against the quick start’s server with clients generated from its manifest; each printed the created todo, 400 https://apue.dev/problems/validation-failed and the titles from the stream.
