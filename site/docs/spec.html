Spec & research

The normative text is SPEC-DRAFT.md (draft 01) in the apü repository, next to eleven research notes and a log of every spike. The toolkit implementing it is apue 0.1.0-beta on npm. The repository is private for now; this page summarises what is in it and where to look.

On this page

  • Goals and non-goals
  • The draft, section by section
  • Open questions

  • Spike log

Goals and non-goals

Goals: one call model for unary, server-, client- and bidirectional streaming with one frame format on every transport; high throughput and short time to first byte, compression, multiplexing; defined purely in RFC 9110 semantics so HTTP/1.1, HTTP/2 and HTTP/3 all work; usable from every browser via fetch() and through ordinary CDNs, proxies and load balancers; fix the top problems of existing styles; TypeScript-first schemas with a language-neutral manifest.

Non-goals: a query language; server-side sessions or sticky connections; relying on trailers, server push, 1xx responses, custom HTTP/2 frames or settings, h2c in browsers, or GET with a body.

Open questions

Every open question of draft 01 is now decided, or blocked by the platform:

  • Resolved while drafting: idempotent operations use POST + key, not PUT; QUERY through CDNs (rejected by CloudFront and Akamai → POST fallback); browser duplex via the WebSocket tier; compression per stream with per-burst flush; projection syntax as dotted paths; resumable uploads; callers and auth via the principal hook; long-running operations as a pattern.
  • Decided against, with measurements or reasons: CBOR (codec and validation are about 11 % of server CPU in a unary call; generic CBOR was slower to encode than JSON and often larger after compression); message-level CREDIT frames (consumer pacing by patterns); per-frame compression (the flag bit stays reserved); Location on QUERY responses; $map in batches.
  • Blocked by the platform: WebTransport (T4) and HTTP/3 in Node. The official Node 26.12.1 build is compiled without QUIC (node_use_quic: false). apü works behind an HTTP/3-terminating proxy; native T4 follows once Node ships a QUIC server.
  • Generators: TypeScript, Python, Go and Java exist; Swift is in progress. Kotlin code calls the Java client.
  • A full DPoP profile — deferred until a DPoP authorization server is in play; the groundwork exists.
  • Problem type namespace: https://apue.dev/problems/<type>; every type has a page on this site.

S16–S17Code reviews with fixes; flow control for the WebSocket tier (apue.v1)

S21–S23Callers: principal hook, credentials over WebSocket, no ambient credentials cross-origin; bounded shutdown; in-band credential errors
S24–S27Uploads that survive a restart; consumer pacing and DPoP groundwork; downloads and CBOR closed; Python clients
S28Production readiness: the npm package and release pipeline, replicas (shared idempotency stores, instance routing verified through nginx), OpenAPI 3.2, a logger option, decisions on every remaining item
S29Clients: Python complete (resume, batches, compression, validation), Go (full duplex) and Java

The suite stood at 391 tests after S29, including runs in headless Chrome, Firefox and WebKit. Every bug the verification found is listed with its fix in the spike log and in docs/status.md.
