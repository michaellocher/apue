Docs / Problem types

409application/problem+json

Idempotency Key In Progress

A request with the same Idempotency-Key is still being processed.

Type URIhttps://apue.dev/problems/idempotency-key-in-progress

When it happens

Non-safe unary calls carry an Idempotency-Key; its scope is the operation, the caller and the key. When a second request arrives in that scope while the first is still running — a client retried before the original answered — the second gets this 409 instead of executing the call twice.

Members

An RFC 9457 problem details object. Besides the standard members it may carry:

type
https://apue.dev/problems/idempotency-key-in-progress
title
Idempotency Key In Progress, the same for every occurrence of this type.
status
409 (response)
detail
A human-readable explanation of this occurrence; don’t parse it.
retryable
true — repeating the same request later may succeed.

Example

How clients should react

  • Wait and repeat the request with the same key and the same payload. Once the original has finished, the stored response is replayed (apue-replayed: ?1).
  • The TypeScript client does this by itself: a 409 with retryable: true is retried with backoff. Any other 409 is not.

Raised in src/server.ts, src/idempotency.ts of the reference implementation. See also: Idempotency keys, Errors.
