Problem types

apü errors are real HTTP status codes with RFC 9457 problem details. Its own protocol errors have a type under https://apue.dev/problems/; each of those URIs resolves to its page here.

  • 400validation-failedThe input does not match the operation’s input schema.
  • 404unknown-operationNo operation with that name exists on this server.
  • 400invalid-selectionA field selection (?s=) names a path the output schema doesn’t have.
  • 400
    502    malformed-streamA framed body contains frames that can’t be decoded.
  • 400
    502    truncated-streamA framed body ended before its END frame.
  • 504deadline-exceededThe call’s deadline (apue-timeout) passed before it completed.
  • 410download-expiredAn Idempotency-Key replay whose stored result refers to a download that has expired.
  • 409idempotency-key-in-progressA request with the same Idempotency-Key is still being processed.
  • 422idempotency-key-reusedThe Idempotency-Key was already used with a different payload.
  • 400invalid-batchA pipelined batch failed structural validation; nothing was executed.
  • 400unresolvable-referenceA $ref points to a path that the referenced call’s output doesn’t contain.
  • 424failed-dependencyA batch call was not executed because a call it references failed.
  • 400invalid-resume-tokenA resume token is malformed, forged, expired or for another call.

Generic errors

Everything else uses the type about:blank with the HTTP status phrase as title — for example 405 Method Not Allowed (with an Allow header), 408 when a request body doesn’t arrive in time, 413 beyond the size limits, 415 for a wrong content type, 429/503 (retried by clients, honouring Retry-After). Unexpected handler errors are a 500 without details. Errors your handlers throw can use types of your own.

Extension members

retryable
Boolean: repeating the same request later may succeed (e.g. idempotency-key-in-progress, or a 503 while a server shuts down).
fields
Per-field validation errors, [{ path, message }] (validation-failed).

Where problems travel — responses, END frames of streams and batch lanes — is described in Errors.
