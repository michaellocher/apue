Docs / Problem types

400application/problem+json

Invalid Resume Token

A resume token is malformed, forged, expired or for another call.

Type URIhttps://apue.dev/problems/invalid-resume-token

When it happens

Resumable streams send signed CHECKPOINT tokens; after a lost connection the client re-sends the call with apue-resume: <token> (SSE: Last-Event-ID). The server refuses a token that is malformed, signed with another secret, expired (15 minutes by default), or issued for another operation or input — and, with a principal hook, for another caller. detail says which.

Members

An RFC 9457 problem details object. Besides the standard members it may carry:

type
https://apue.dev/problems/invalid-resume-token
title
Invalid Resume Token, the same for every occurrence of this type.
status
400 (response, before the stream starts)
detail
A human-readable explanation of this occurrence; don’t parse it.

Example

How clients should react

  • Don’t resend the token: it won’t become valid. Start the stream again without it, from the beginning or from an application-level cursor in the input.
  • Behind several replicas, every replica needs the same resume.secret.

Raised in src/resume.ts of the reference implementation. See also: Resumable streams, Errors.
